# Use cases

> Draft audience guide for review.

Start with a real task and the context already available for it. Context Fabric
can support one person's work, a team's recurring questions or coordination
across organizational boundaries. These are useful scopes, not required
adoption stages.

The [Start here guide](../../START-HERE.md) owns the complete first-use prompt.
Reading an existing view and drafting from accessible evidence require no
installation. Local authoring, validation and generation require a supported
framework route and successful checks.

## For Individuals

Use a maintained view to prepare a briefing, find the systems involved in a
change, or get oriented before a handoff. The view gives you a starting account
of relevant systems, evidence and known gaps, so each task does not require the
same landscape to be reconstructed.

Begin with one useful task and share the relevant documents, source links or
existing view. When local authoring and validation are available, supported
facts can become reusable context. Otherwise, the agent can still help read or
draft and must identify the result as unvalidated. Inspect the fictional
[Meridian Health Agency view](../../views/meridian-health-agency/view.yaml) for
an example.

Your private paths and access settings remain in an Individual document,
separate from shared facts. You do not need a team-wide rollout to start.

**[Start with your task](../../START-HERE.md).**

## For Teams

Use shared context when onboarding, handoffs or change assessments repeatedly
require the team to reconstruct the same systems and sources. Org documents
hold shared facts; a Bounded Context selects what matters for a team, product or
workstream; Individual access settings remain private.

Choose one recurring task and the sources the team already trusts. Agree who
maintains the facts and how changes will be reviewed. The framework checks
structure and references, while people assess whether the facts are supported
and useful. Discoveries can become correction proposals for the responsible
maintainer. Drafts and skipped checks remain visible as such.

**[Start with your team's task](../../START-HERE.md).**

## For Organizations

Use connected context when a change, workflow or handoff crosses team and
system boundaries. Teams can reference shared facts where they are maintained
instead of updating separate explanations. Generated views carry source
releases and provenance; correction proposals and releases support coordinated
updates.

Start with work that already needs cross-team discussion. Participating
maintainers establish ownership, evidence, access and release practices. The
framework validates structure and references, not the truth of unsupported
claims. Existing tools continue to provide permissions and access controls;
Context Fabric does not provide a hosted administration console or identity
service.

Review the [strategy](strategy.md) with participating maintainers as the scope
grows.

**[Start with the shared task](../../START-HERE.md).**

## Choose a setup route

The use case does not determine the distribution. Reuse an existing view or
checkout when it fits. For local framework work, compare the normal checkout,
draft-only and prepared archive routes in
[manual setup](../manual-setup.md#choose-a-distribution-for-local-work). The
[no-clone bundle](../bundle-start.md) has separate lookup and lifecycle limits.
