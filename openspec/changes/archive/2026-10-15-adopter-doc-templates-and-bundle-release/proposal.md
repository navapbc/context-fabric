# Proposal

## Why

A private adoption trial showed three gaps in what the framework hands an adopter. The agent hand-wrote the workspace root `AGENTS.md` and got the bootstrap wrong, because nothing produces that file and the Org documentation guide describes the README and maintenance doc only as prose. The no-clone bundle is built and proven in CI, but only as a workflow artifact, and three documents say a permanent download channel has not been selected. And no spec says skill names or the `.agents/skills/<name>/SKILL.md` layout stay put, although contracts already moved from 1 to 2 to 3 inside 0.x, so an adopter document that hardcodes a skill path goes stale without any finding.

## What Changes

- The develop-org skill ships fixed-slot templates for the workspace root `AGENTS.md`, the README and the maintenance document, with one table of slots and fill rules. The one-pager stays judgment-based guidance. The root `AGENTS.md` routes reading to the named view's `AGENTS.md`, and routes authoring through the Individual binding's `framework_root`, with a fallback that needs no binding.
- A repository test fills the templates and fails on an unresolvable local link, a skill name that does not exist, a hardcoded skill path, a branch-pinned URL, a machine path, a secret reference, or a slot with no fill rule.
- CI builds a checksum beside the bundle archive, verifies the pair, and uploads both. A maintainer publishes them as attachments to a GitHub Release, by hand. The docs name that channel and give the maintainer steps, including superseding the retired Starter Kit's `v0.2.0` as the Latest release.
- Adopter documents name a skill as `skill:<name>` and resolve it through the binding's `framework_root`. The skill-bundles spec states that skill names and layout do not change within a minor version, and that a rename or move is a recorded breaking change with an old-to-new pointer in the shared rules.
- The maintenance template records the framework version and the tag or commit in use.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `develop-org-skill`: reader documents come from templates, and the root `AGENTS.md` is allowed as a routing file.
- `no-clone-bundle`: CI exposes the archive with a checksum, and a maintainer publishes both as a release attachment.
- `skill-bundles`: skill names and layout are stable within a minor version.

## Rejected alternatives

- **Keep the documentation guide as prose.** The agent rewrote the structure each time and the one file that matters most for bootstrap was never described.
- **Put the templates under `templates/`.** That folder is generated by `scripts/render-templates.sh`, and a hand-written file there fails the freshness check.
- **Publish the bundle to a package registry.** The bundle is one archive and runtime commands never fetch dependencies, so a registry has no consumer.
- **Create the release from CI.** Releases are human-only repository administration in `.github/CONTRIBUTING.md`; CI builds and verifies and a person publishes.
- **Hardcode skill paths or `main` links in adopter documents.** They break silently when a skill moves.
- **Vendor skill copies into adopter repositories.** A copy cannot follow the framework's contract and no check would notice it age.
- **Alias tooling for renamed skills.** No rename is planned; the spec states the rule and where the pointer goes, and the section is created at the first rename.
- **A checksum signature or provenance attestation.** A checksum beside a maintainer-published archive answers integrity; signing waits for a consumer who needs to verify the builder.

## Impact

- New files under `.agents/skills/develop-org/assets/adopter-docs/` and a new test `tests/adopter-doc-templates.test.sh`.
- Edits to `.agents/skills/develop-org/assets/org-documentation.md`, `.agents/skills/develop-org/SKILL.md`, `.github/workflows/check.yml`, `docs/tool-routes.md`, `docs/maintenance-interface.md`, `docs/experiments/README.md` and `docs/CHANGELOG.md`.
- Spec deltas on archive for the three capabilities above.
- No script under `scripts/`, schema, contract version, finding code or generated-view change. The templates ship in the next bundle build.
