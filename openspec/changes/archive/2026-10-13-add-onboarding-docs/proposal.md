# Onboarding and task-time routing

## Why

The entry point is a skeleton, and installed instructions incorrectly assume a
view sits beside them. An agent starting in a bound product checkout needs to
reach the named view without reading framework documentation.

## What Changes

- Explain public access, the three adoption paths, external documents roots,
  authoring fields, and honest validation and evidence gaps.
- Route portable instructions to the adjacent view and installed instructions
  through the named Individual binding; check retention at the resolved view.
- Index local guidance, cross-check its links and entry ordering, and record
  experimental evidence separately from governed facts.
- Keep the colleague rehearsal and unfinished walkthrough rows explicitly open.

## Rejected Alternatives

- Requiring authenticated access to the public framework adds a false barrier.
- Calling template drafts validated hides the checks and views they lack.
- Rewriting installed instruction copies breaks exact-copy delivery; routing in
  the shared template serves both placements.
- Treating agent walkthroughs as colleague adoption invents acceptance evidence.
- Advertising an unimplemented bundle command gives adopters a broken path;
  document its pending status until the packaging capability lands.

## Impact

Onboarding documentation and generated instruction wording change. Schemas,
script interfaces, installer behavior, and shared facts do not change.
