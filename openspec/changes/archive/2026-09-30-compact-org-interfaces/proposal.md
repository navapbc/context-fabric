## Why

Shared catalogs carry repeated prose and do not distinguish service endpoints from discovery links. Agents need compact objective routes and a narrow way to find relevant records without loading every detail.

## What Changes

- Introduce immutable Org 2 and view 2 contracts, retaining BC and Individual 1.
- Replace interface notes with classified locators and optional typed route, capability and read-only probe descriptors; exclude machine-local resources.
- Preserve old notes and probe intent in private migration review receipts, even when normal backups are declined.
- Consolidate host-tool guidance and add an index inside the existing standalone view.
- Improve discovery guidance, actual application entrypoints and private access evidence.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `org-contract`: Compact objective interface descriptors and no local resources.
- `view-contract`: In-view index and consolidated authentication explanation.
- `release-mechanics`: Target validation and private review receipts during migration.
- `view-generation`: Stable interface presentation and standalone selective loading.
- `develop-org-skill`: Optional authoritative source guidance and bounded direct access checks.

## Impact

Current Org documents require migration and generated views require regeneration. IDs and authentication binding names remain stable. Existing contract directories remain unchanged. No authored probe is executed by validation or generation.

## Rejected alternatives

- Editing frozen v1 contracts would break existing readers; add versioned contracts instead.
- Inferring endpoints or capabilities from legacy prose would fabricate facts; preserve unknown locator roles for author review.
- Discarding legacy notes when backups are declined would lose context; preserve them in a private review receipt before any authored write.
- Adding a retrieval service or a fourth context artifact would expand the task-time boundary; keep the discovery index and complete selected facts in the existing view.
- Storing personal access outcomes or local resources in Org would confuse shared capability with one session's configuration; keep those observations private.
