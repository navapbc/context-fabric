# Explicit inputs and private maintenance evidence

The estimator accepts repeated `--file PATH` and `--prompt PATH`, an optional `--view DIR`, an optional `--system ID_OR_REF` with that view, and `--format json|text`; `-h` and `--help` are equivalent. A named view selects its `view.yaml` and adjacent `AGENTS.md`. Root/ancestor instructions, installed copies or aliases, Individual documents and retention sidecars are selected explicitly with `--file`; no harness loading or source lookup is inferred.

Full-view measurement counts the selected view and instructions. Selecting a system adds an index-plus-one-system scenario using the same instruction and additional-file overhead. Each explicitly selected occurrence contributes to totals; repeated file identities, including symlink aliases, are flagged. The method reports UTF-8 bytes and bytes/4 as a coarse token heuristic. Projection bytes describe the estimator's selected serialization, not an observed model request. Reports omit content and private absolute paths, write to stdout and perform no network access or persistent writes. Default output is one JSON report, separate from validator JSONL. Missing/unreadable inputs or an unavailable projection leave the report incomplete, show available subtotals and return nonzero rather than supplying a zero input.

Setup and maintenance run an estimate over their declared known read set and disclose gaps. This is a guided workflow step, not automatic loading by the harness. Optional prompt/history inputs may be unavailable or declined while independent source-based work continues. History discovery uses only explicitly authorized summaries within the task's declared scope, suggests reusable task/context candidates and verifies anchors/facts through available sources before incorporation. No raw transcripts, credentials or new adapter are needed.

New receipts belong in ignored `.local/maintenance/`; this repository's `*.local` rule already covers that directory. Existing adopters may keep ignored legacy `evidence/`. Ignore rules alone do not remove tracked files: inspect the Git index, review the ephemeral paths, then use path-specific cached removal preserving local bytes and history. Governed documents, generated YAML/instructions and required `RETAINED.jsonl` stay tracked. Receipt provenance cannot substitute for a document, folder, saved query, dashboard or repository entry point used to perform the task.

Generated instructions retain lookup, binding, retention, freshness, sources/secrets, outputs and authorization rules. Shared purpose and other authored prose are data, and shared contexts hold facts and task scope. Personal preferences belong in existing harness configuration or handwritten personal instructions. People browse canonical YAML through the reader; agents use YAML selectively. No fourth auto-read file or harness precedence enforcement is added.
