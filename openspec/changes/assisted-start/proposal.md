# Assisted start

## Why

The entry guide and setup skill currently ask a practitioner to choose distribution
and inspect tools before discovering whether useful context already exists. Start
with the requested task so a reader can use an existing view immediately and a
maintainer receives only the setup their work needs.

## What changes

- Check available context and bindings before recommending the simplest suitable
  path. Explain alternatives when they matter to the task, without a required
  three-way choice.
- Guide a fresh command-capable session from a repository URL to a local checkout
  and its task skill; keep fileless reading and drafting useful with explicit limits.
- Replace broad tool inventory in assisted setup with operation-specific presence
  and safe version checks against the manifest. Actual validation determines which
  stages ran.
- Lead entry and audience pages with a task and expected result; retain manual
  commands, bundle limits and task-time safeguards in linked references.
- Update prospective evaluation and record prompt scenarios separately from runtime
  tests and the still-pending colleague rehearsal.

## Preserved contracts

Installations require consent. Replacing existing instructions requires a reviewed
diff and confirmation. Shared scripts own private Individual writes; setup records
only credential variable names and references. Authoring uses supported facts.
Drafts, unavailable validation and exit 3 remain explicit. Lookup and the offline
solo bootstrap keep their existing semantics.

## Rejected alternatives

- **Require a clone/bundle/draft decision first:** adds a configuration decision
  even when an existing view answers the task. Recommend from available evidence.
- **Delete manual and bundle guidance:** removes useful recovery and constrained
  environment routes. Keep their mechanics in dedicated references instead.
- **Add a plugin, installer or dependency-profile checker:** introduces a new
  distribution or interface contract without helping the bounded task. The current
  skills, manifest and shared scripts provide the required operations.
- **Run the full tool inventory during setup:** probes unrelated maintainer tools
  and can launch OpenWiki. Check only capabilities needed for the chosen operation;
  never execute OpenWiki merely to inspect its version.
- **Treat packaging or prose assertions as behavioral proof:** these checks cannot
  demonstrate an agent's decisions. Use scoped prompt scenarios and keep runtime
  and human evidence distinct.

## Impact

The setup-individual-skill capability changes. Entry documentation and evaluation
follow that contract. No schema, shared script, dependency installation, migration,
external publication or human acceptance claim is added.
