## Why

A newcomer meets one generic prompt and a list of redirect headings. The task-to-skill route sits in a setup document, `setup-individual` quietly acts as the router, and reporting a wrong fact or promoting a private Bounded Context has no clear home. The skill folder mixes four product skills with generated OpenSpec skills that need a CLI most users do not have, and rules such as peer-folder naming, exit codes and the Individual-write rule are repeated in several places and have drifted.

## What Changes

- `.agents/skills/` holds only user-facing skills. The generated OpenSpec skills and commands leave the repository and are gitignored; `check-skills.sh` enforces the boundary.
- A tool-free `start-here` skill routes a user by what exists, where a Bounded Context should live, and whether they are reading or changing. A `handle-corrections` skill covers proposing, reviewing, accepting and declining corrections; `setup-individual` returns to machine binding and the solo bootstrap.
- Rules several skills repeat live once in `.agents/skills/start-here/references/shared-rules.md`; skills link to it.
- `START-HERE.md` becomes a decision table plus the one prompt, naming skills by path. Setup, bundle and dependency documents consolidate into `docs/tool-routes.md`; `docs/maintenance-interface.md` becomes an agent reference.
- The no-clone bundle ships the product skills without their script wrappers.

## Rejected alternatives

- An OpenSpec-style packaged CLI: it adds an install, moves workflow text out of reviewable skill files and duplicates the scripts surface.
- Sequencing the three parts as separate changes: the owner wants them delivered together.
- Committing the generated OpenSpec skills: they are contributor tooling regenerated by `openspec init` and `update`.
- Extending the bundle's script set: out of scope; skills state which steps need a checkout.

## Capabilities

### New Capabilities

- `start-here-skill`: The entry skill and the shared-rules reference.
- `handle-corrections-skill`: The correction skill.

### Modified Capabilities

- `skill-bundles`: Six canonical skills, an explicit boundary against contributor skills, skills-root links.
- `setup-individual-skill`: Narrowed to machine binding and the solo bootstrap.
- `validate-and-generate-skill`: Corrections move out; no OpenSpec references.
- `develop-bounded-context-skill`: Promotion from private to shared.
- `repository-entry`: Decision-table entry, one tool-route document, agent-facing command reference.
- `no-clone-bundle`: The bundle ships the product skills.
